# 问题二确定性核验记录

**结论：本流程是「决策可复现」，不是「逐位可复现」。** 论文里必须这样表述。

## 怎么测的

同一条命令、同一份数据、同一随机种子，跑两遍：

```
python q2_train.py --out data/q2 --epochs 60 --text-table distill
```

- 第一遍（run1）的指标快照：`q2_metrics_run1.json`
- 第一遍的模型快照：`q2_model_run1.pt`
- 第二遍（run2）的产物：`data/q2/q2_metrics.json`、`data/q2/q2_model.pt`

两遍**均为**：`best_epoch = 5`，共跑 17 轮后早停。

**附件3 交付预测的核验**：用 run1 的模型快照重新推理附件3，
与 `data/q2/attachment3_predictions.csv`（run2 产出）逐行比对：

- 极性：**30/30 完全一致**
- 强度：最大绝对差 **1.07e-06**

### 存在浮点级漂移的部分

| 项 | 数值 |
|---|---|
| 漂移字段数（共比对 ~900 个数值字段） | 195（全部是 MAE / Pearson / train_loss） |
| 相对漂移中位数 | **9.6e-08** |
| 相对漂移最大值 | **3.4e-04** |

最大漂移出现在 `epoch 16` 的 valid Pearson（0.33657 vs 0.33669）——
**那是早停之后才跑的轮次，不参与任何选择，也不是交付指标**。
交付指标（第 5 轮 valid / test 的 MAE 与 Pearson）的漂移在 **1e-07** 量级。

> 另有 16 个 `.sec` 字段（每轮墙钟耗时）差异最大到 10%，
> 那是计时抖动，与数值确定性无关，不应算作漂移。

## 为什么会漂移（论文里可以这么写）

PyTorch CPU 路径下，多线程归约的**求和顺序**随线程调度变化；
float32 加法不满足结合律，于是同一份输入在不同次运行中会得到
相差约 1e-07 的中间量。这不是实现缺陷，是浮点并行的固有性质。

**但漂移不止于 1e-07——它会被 SGD 放大。** 直接比对两次运行的模型参数：

| 指标 | 数值 |
|---|---|
| 参数张量中发生变化的 | 52 / 53 |
| 参数最大绝对差 | **2.38e-02**（`encoder.pool_score.bias`） |
| 次大 | 1.61e-03（`layers.0.self_attn.in_proj_bias`） |

也就是说：**初始的 1e-07 扰动经 17 轮 SGD 被放大到 1e-02 量级**，
而**交付指标仍然只差 1e-07**。两者都成立，不矛盾——
模型处在一个「参数平缓、输出平坦」的区域：参数可以走远，
但决策边界和曲面上的取值几乎不动。

## 这对问题三意味着什么（重要，必须写进论文）

问题三的归因与因果量是在**同一个模型实例**上算的，因此它继承了这份不确定性：

| 量 | 跨重跑的稳定性 | 说明 |
|---|---|---|
| 文本主导这一**结论** | **稳定** | 注意力占比 0.962 / 0.963；KL 上文本比音视频高 1–2 个数量级；翻转次数上文本 12–13 次 vs 音视频 0–2 次 |
| 主要参考模态 = text | **稳定** | 两遍分别为 20/20 与 19/20 |
| 音视频的**效应量** | **不稳定** | 例如视觉的留一 Δ 两遍分别为 +0.0148 与 −0.0060（**连符号都会变**）；拿掉即翻转的计数 audio 2→0、vision 2→1 |
| 两口径一致率 | 略有波动 | 100% vs 95% |

原因：音频/视觉的效应量本身就在 **1e-02** 量级，与参数漂移同量级，
因此**落在噪声地板附近**，逐位不可复现。

**写法建议**：结论层面说「文本模态占绝对主导」，这是稳的；
不要把音视频的 Δ/KL 第三位小数当作可复现的结论来引用，
也不要用它去论证「音频比视觉更重要」这类二阶命题。

## 问题三：修复后可逐位复现

> 这一节对应 `README.md` §8.10 记录的缺陷：`q3_explain.py` 加载问题二模型后
> **从未调用 `model.eval()`**，`nn.Module` 默认 `training=True`，
> 于是解释路径里 `dropout(p=0.15)` 一直生效，注意力与留一量全是随机量。
> 同一份模型文件重跑会给出不同的「主要参考模态」（实测 20/20 与 19/20 两种结果）。

修复后（显式 `model.eval()` + `attribute_sample` 入口兜底），
同一命令跑两遍（`--out data/q3` 与 `--out data/q3_rerun`）：

| 项 | 结果 |
|---|---|
| `q3_summary.json` 全部字段逐项比对 | **0 个字段不同** |
| 附件4 极性预测 | **20/20 一致** |
| 附件4 强度预测 | 最大绝对差 **0.000e+00** |

即：**问题三现在是逐位可复现的**，比问题二更强（问题二受 SGD 放大影响，
参数层有 1e-02 漂移）。

修复前后的对照（同一模型、同一命令）：

| 量 | dropout 生效时（错） | eval 后（对） |
|---|---|---|
| 文本注意力占比 | 0.962 ~ 0.976 | **0.970** |
| 留一 KL · 音频 | 0.0091 ~ 0.0176 | **0.0022** |
| 留一 KL · 视觉 | 0.0143 ~ 0.0228 | **0.0112** |
| 拿掉即翻转 | audio 0~2 / vision 1~2 | **audio 0 / vision 1** |

注意音频的 KL 从约 0.015 降到 0.0022——**差了一个数量级**。
原先那些值基本是 dropout 噪声，不是模型对音频的真实依赖。
因此**修复前生成的任何问题三数字都不可引用**。
