# 为什么这个目录存在：验证 D1 修复没有改变问题二的结果

本目录是 `python emotion_model.py --cv-only`（默认三模态）的一次**复跑产物**，
不是交付物、也不覆盖 `data/model/`。它存在的唯一目的，是回答一个问题：

> `align_multimodal.py` 把落盘的 `duration`/`slot_edges` 由 float32 改成 float64（代号 D1）
> 之后，问题二（情感强度回归 + 状态分类）的指标变了吗？

**结论：没有变。** 本次复跑与 `data/model/README_情感判定模型_运行结果.md` 逐项一致。

| 指标（Ridge 回归） | `data/model/README_...md`（修改前那次全量运行） | 本次复跑 |
|---|---|---|
| MAE | 0.527 | 0.52682 |
| r | +0.413 | +0.41317 |
| ρ | +0.505 | +0.50524 |
| acc | 0.602 | 0.60152 |
| macroF1 | 0.326 | 0.32583 |
| 平衡 acc | 0.389 | 0.38889 |

消融同样一致（vision r=+0.130、text+vision r=+0.432、audio 单独为负等）。

## 为什么可以断定「不是碰巧一致」

1. `emotion_model.py` 是**确定性**的：连续两次 `--cv-only` 到两个不同目录，
   `cv_comparison.csv` / `ablation.csv` / `oof_predictions_all100.csv` 三份文件
   **逐字节相同**（已实测）。所以「指标变了」只可能来自输入数据变了。
2. 输入数据没变：`data/aligned/` 下 100 个逐样本文件的三模态 `*_features` 与
   `*_valid` 掩码，与 D1 修复**之前**的备份 `data/_backup_20260924/` 逐元素 md5
   完全一致（0 个不一致）；`aligned_50.npz` 里除 `duration`（即 D1 有意改的 dtype）
   之外全部一致。
3. `emotion_features.build_design_matrix()` 只读 `aligned_50.npz` 的
   `{m}_features`/`{m}_valid` 加标签表——正好是第 2 条里被证明没变的部分。

## 顺带发现的一处**既存**不一致（记作 M1，早于 D1，不是 D1 造成的）

> 编号说明：本条曾随手记作「D3」，但问题一交付层另有一条真实代码缺陷也叫 D3
> （`face_probe.py` 用按主键建字典的读法去读逐帧表，见
> `data/q1_delivery/anomaly_ledger.csv` 的 `D3_FRAMES_TABLE_KEYED_READER`）。
> 两条无关，此处改记 **M1**（M = 问题二 model 目录）以免混淆。

`data/model/` 里有两个文件与同目录的 `README_情感判定模型_运行结果.md` **互相矛盾**：

- `data/model/cv_comparison.csv` 的 Ridge 行是 MAE 0.5356 / r +0.3967 / ρ +0.5200，
  与 README 的 0.527 / +0.413 / +0.505 **不同**；
- `data/model/ablation.csv` 只有 4 行（应为 7 行），且最后两行重复。

已实测证明原因：这两份文件是 **`--modalities text,audio`（只用文本+语音）** 那一次
`--cv-only` 的输出——用同样的命令重跑，得到的两份文件与它们**逐字节相同**。
也就是说它们是「只跑了两个模态」的旧结果，被留在了 README 旁边，
而 README 是三模态全量运行生成的。

这与 D1 无关：D1 只改了 `duration` 的落盘 dtype，不碰任何特征数组。
按「不破坏本次版本」的要求，**本目录不覆盖也不删除 `data/model/` 里的任何文件**，
只在此如实记录，交由作者决定是否重跑问题二以统一口径。

## 一处 D1 尾巴：`data/aligned/slot_time_map.csv`（**已闭环**）

`align_multimodal.run()` 的尾部会写两个**派生**的 CSV：

```
save_aggregate → save_slot_time_map → save_summary_csv
```

`slot_time_map.csv` 被外部程序（WPS 表格）占用，写它时抛 `PermissionError`，
连带 `save_summary_csv` 也没机会执行——于是 `align_summary.csv` 一度停在旧版本
（含 D2 的 18 行 `official_id` 缺陷）。

**处理结果（已实测）**：

| 文件 | 状态 |
|---|---|
| `data/aligned/align_summary.csv` | ✅ 300 行、`official_id` 不符 **0** 行 |
| `data/aligned/slot_time_map.csv` | ✅ 5000 行（100 样本 × 50 槽），与 `slot_edges` 逐边界零偏差 |

### 处理过程中暴露的两件事（都值得记下来）

**其一：该文件当时不是「旧表」，而是「空表」。** 恢复脚本写它时用的是
`open(path, "w")`——这个调用**先截断再写**。上一轮脚本死在半途，于是在
`PermissionError` 之外还留下一个只剩表头的 145 字节文件。也就是说文件处于
「**看起来存在、但一行数据都没有**」的状态，比「内容陈旧」更危险：只查大小或
只 `ls` 一眼，很容易把它当成正常产物。核对这类派生表**必须数行数**，不能看存在性。

**其二：恢复脚本自身有一处缺陷（记作 T1，T = 一次性恢复工具的 tooling）。**
`_regen_summary_tail.py` 从单样本 npz 重建 `results` 时，把 `align_meta` 直接取成
文件里的 `meta[m]["align"]`，而落盘时 `slot_unit_index` 是**被有意从 `align` 里提出来、
放到模态一级**的：

```python
# align_multimodal.save_sample_aligned()
"align": {k: v for k, v in md["align_meta"].items() if k != "slot_unit_index"},
"slot_unit_index": md["align_meta"]["slot_unit_index"],
```

而 `run()` 内存里的 `align_meta` 是**含** `slot_unit_index` 的完整 meta。
缺了这个键，`save_slot_time_map()` 读 `md["align_meta"]["slot_unit_index"][k]` 立即
`KeyError`——而 `main()` 只捕获 `PermissionError`，所以这个 `KeyError` 直接终止脚本。
修法是把两者拼回去：

```python
"align_meta": dict(meta[m]["align"], slot_unit_index=meta[m]["slot_unit_index"]),
```

### 新表的核验口径（不是「跑完就算」）

1. **与 D1 修复前的备份逐值对照**：`data/_backup_20260924/aligned/slot_time_map.csv`
   （5000 行，D1 之前生成）。结果：8 个非浮点列**不一致 0 行**；4 个浮点列
   `duration_sec / t_start_sec / t_end_sec / t_center_sec` 的最大绝对偏差均为 **0.000e+00**。
   这是预期的——D1 只把 `duration` 的**存储精度**由 float32 提到 float64，差异约
   1e-7 秒量级，远在该表 4 位小数的打印精度之下。**所以 D1 对本表数值无影响，
   变的只是它的生成时间戳与生成来源。**
2. **与 `data/aligned/*.npz` 独立对照**：用 100 个单样本 npz 里的 `slot_edges`
   逐边界比对，100 样本 × 100 个边界 = 10000 个边界，最大偏差 **0.000e+00**。
   这一条才是关键：它证明新表与**当前**对齐产物自洽，而不只是与旧表一致。

### 影响范围与结论

`slot_time_map.csv` 是**给人看的派生表**（槽号 ↔ 秒的对照），不是特征数据：
它不参与任何特征计算、不进模型、不被 `q1_verify.py` 或交付文档引用
（已 grep 确认：`data/q1_delivery/` 与 `q1_verify.py` 中零处提及）。因此这一环的
修复**不改变任何特征、对齐结论或问题二结果**，它解决的是「溯源链上有一环没跟着重写」。

复现命令（需先关掉 WPS 里打开的这个文件）：

```cmd
cd D:\23届建模\code
python _regen_summary_tail.py
```

`_regen_summary_tail.py` 不重新对齐，而是从已写好的单样本产物重建 `results`
再调用同一个 `save_slot_time_map()` / `save_summary_csv()`，产出与正常跑完
`align_multimodal.run()` 一致。它**不属于常规流程**（不在交付物
`extract_config.json` 的 `reproduce` 序列里），只在文件被外部占用时作为绕行手段使用。
