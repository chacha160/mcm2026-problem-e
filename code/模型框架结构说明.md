### 1.4 两处必须说清的输入口径差异（实测，非推测）

1. **赛题正文的时长区间与文件实际不符。** 正文称「所有视频时长介于 2.648 秒和 34.567 秒之间」；用 `ffprobe` 对全部 100 个 mp4 实测（容器时长与视频流时长两口径完全一致）**实为 2.257 ~ 29.288 s**。本项目全流程以 **ffprobe 实测值**为准，不做裁剪；`q1_verify.py` 的 V8 项用外部 ffprobe 重新核对。
2. **不能用「帧数 ÷ fps」估时长。** 本批 mp4 容器帧数**虚高 1.5~2.6 倍**（例：`-3g5yACwYnA/2.mp4` 容器声称 424 帧 @30 fps = 14.13 s，实际只解出 278 帧、真实 9.39 s）。旧工具 `utils.get_video_duration()` 正是这么算的，会把时间轴整体拉长；现流水线一律用 ffprobe 流时长 + 逐帧实测 PTS。

### 2.3 各模态特征怎么提（三张表说清）

| 模态 | 方法 | 维度 | 单元 | 时间基准 |
|---|---|---|---|---|
| **文本** | 冻结的 `roberta-base` → `last_hidden_state`；子词按词（`word_ids`）求均值 → 词级向量 | 768 | 词 | `uniform_assumption`（**假设**，非实测） |
| **语音** | `librosa`：MFCC 20 + ΔMFCC 20 + ΔΔMFCC 20 + logF0 + 浊音概率 + logRMS + ZCR + 谱质心/带宽/滚降/平坦度 + 谱对比度 5 + VAD | 74 | 帧 @20 Hz | `measured_pts`（实测） |
| **视觉** | MTCNN(`image_size=160`, `keep_all=False`) 裁人脸 → Resize(224) → ResNet-50 去掉 fc 的 2048 维全局池化 → 固定随机投影（seed=42，`W∈R^{2048×35}`）降维 | 35 | 帧 @15 Hz | `measured_pts`（实测） |

两条必须如实标注的事实：

- **语音 74 维是「等价维度代理」**：官方 74 维来自 COVAREP（含声门参数 NAQ/QOQ/H1H2），本机无 COVAREP，故改用「MFCC + 差分 + 韵律 + 频谱」凑满 74 维，并**逐段写进文件元数据**（`meta.dim_layout`）以便复核。论文中不得声称使用了 COVAREP。
- **文本没有真实逐词时间戳**：附件1 只给整句转写，附件2 也不存逐词时间戳。故词级时刻只能来自假设 `词 i 中心时刻 = (i+0.5)·T/W`，`meta.time_basis` 如实记为 `uniform_assumption`，与音频/视觉的 `measured_pts` 硬证据区分开。**因此本项目不声称达到任何毫秒级对齐误差**——没有逐词人工真值就无法量化。

### 2.4 对齐规则（问题1 的数学核心，六条）

> **一句话**：以片段真实时长 `T` 为公共时间轴，把 `[0,T]` 等分为 `L=50` 个槽（槽宽 `T/L`）；每个未对齐单元按其**实测时间戳**归属到所在槽，同槽内特征取**均值**；空槽按策略补齐并在 `valid_mask` 中标 `False`。

1. **按「秒」归属，不按数组下标**——三模态采样率不同（音频 20 Hz、视觉 15 Hz、文本按词），按下标等分会把 50 ms 的音频帧与 66.7 ms 的视觉帧当作等长，并抹平丢帧/VFR 的不均匀间隔。
2. **三模态共用同一个 `T`**——取自 ffprobe 视频流时长，提取阶段就写进各模态 `meta.duration_used`；因此**对齐这一步不需要原始视频**，仅凭未对齐特征文件即可独立重跑。
3. **空槽策略按模态疏密分别设定**——文本 `zero`（5 s 的话只有十几个词，天然填不满 50 槽；补零才诚实，插值会制造原文不存在的「词」）；语音/视觉 `interpolate`（采样率远快于槽率，空槽只可能出现在音轨短于视频处）。
4. **槽 ↔ 时间是可逆闭式映射**（问题3「关键证据定位」能回落到真实时段的前提）：
   ```
   槽号 → 时间： [k·T/L, (k+1)·T/L)
   时间 → 槽号： min(L-1, floor(t·L/T))
   ```
5. **比闭式公式更强的是溯源链**：每槽同时记录「哪些未对齐单元落进了它」（`slot_unit_index`），于是 `槽号 → 未对齐单元下标 → 该单元的原文词 / 该帧时间戳` 这条链是完整的。`q1_verify.py` 的 V4 项正是用这条链反向重算（取每槽源单元重新求均值，要求与落盘槽值**逐元素精确相等**）。
6. **越界单元必须记账**：`pts` 超出 `[0,T]` 的单元并入首/末槽，同时记 `units_clipped_to_last_slot` / `units_clipped_to_first_slot` / `units_beyond_duration` 三个计数（实测 5 条样本视觉末帧 PTS 超出公共时间轴 0.033~0.067 s）。

### 3.2 `config.py` 中的**遗留/漂移**常量（重要）

`OUTPUT_DIR` / `TEMP_AUDIO_DIR` / `SUMMARY_CSV` 指向**已删除的上一版流水线**（`extractors/ + main.py + alignment.py + report.py`）产物，当前无任何代码使用；`VIDEO_FPS = 25`、`AUDIO_HOP_LENGTH = 512`、`TEXT_ALIGN_STRATEGY = "word_interpolate"` 也与当前实际用法不一致（当前视觉默认 15 Hz、音频 hop=800@16k=50 ms、文本走「未对齐提取 + 按秒对齐」而非插值到 50 步）。

> **判断实际生效的参数，请读产物里的 `meta` 或 `data/q1_delivery/extract_config.json`，不要读 `config.py`。** 这些常量保留只是为了 `check_data.py` 之类的诊断脚本仍可 import 而不报 `AttributeError`。

### 3.3 `*_valid` 掩码的语义边界（最容易误用的一条）

`valid=True` **只表示「该槽被分配到了采样单元」，不表示该单元是真观测**——插值与零填充同样被标 `True`。

反例（实测）：`-mJ2ud6oKI8_1` 的 `vision_valid` 是 50/50 全 `True`，但其视觉特征能量**恰为 0.0**（MTCNN 一帧人脸都没检出）。

判断模态是否真的可用要用**原始 `face_ratio`**（`emotion_features.load_availability`），不能用 `*_valid`。同理，文本 `*_valid` 只占 43%（每条中位 20/50，因为只有十几个词）。

### 3.4 文件格式契约（三族 npz）

**① 未对齐单模态** `data/unaligned_features/<modality>/<sample_id>.npz`
键：`features (T,D) float32`、`pts (T,) float32`、`modality`、`meta`（JSON 串）、`extra__<key>`（JSON 串，如 `extra__envelope`、`extra__face_flags`、`extra__words`、`extra__char_spans`、`extra__token_index`、`extra__frame_gaps`）。
> 说明：不存在 `face_boxes` 字段（`keep_all=False` 不保留框坐标）；一律走 JSON 而非 ndarray，是因为字段不等长、含字符串，且 `allow_pickle=False` 下无法存 object 数组。

**② 对齐单样本** `data/aligned/<sample_id>.npz`
键：`sample_id`、`duration`(float64)、`slot_edges`(float64, L+1)、`n_slots`、`{m}_features (L,D) float32`、`{m}_valid (L,) bool`、`meta`（JSON 串，每模态含 `num_units/feature_dim/src_duration/time_basis/align/slot_unit_index`）。

**③ 对齐汇总** `data/aligned/aligned_50.npz`（附件2 口径）
键：`sample_id (N,)`、`duration (N,) float64`、`n_slots`、`{m}_features (N,50,D) float32`、`{m}_valid (N,50) bool`、`{m}_features_dim`、`{m}_lengths`。

**④ 问题1 交付特征** `data/q1_delivery/features_q1.npz`（**变长不补零**，与 ③ 互补）
键：`sample_id (100,)`、`n_samples`、`pipeline_version`、`text_features (2191,768)` / `text_lengths (100,)` / `text_pts (2191,)` / `text_offsets (101,)`，`audio_features (15588,74)` / `audio_lengths` / `audio_pts` / `audio_offsets`，`vision_features (11790,35)` / … ，各模态另有 `{m}_feature_dim`、`{m}_time_basis`。

### 4.4 三条贯穿全项目的「设计契约」

1. **对齐层是唯一的「定长张量」产出者**：只有 `align_multimodal.py` 产出 `(50,D)` 与槽↔时间映射；`timeline_visualize.py`、`q1_delivery.py`、`q1_verify.py`、`_regen_summary_tail.py` 全部**只读**其产物；跨模块溯源唯一纽带是 `meta.slot_unit_index`。

3. **不删样本**：所有退化样本（音轨数字静音、人脸全失败、视觉能量为 0）**全部保留**在 100 行汇总、特征与台账里，只如实标注异常代号；异常台账里 `counts_as_deletion` **恒为 0**。

### 5.3 L1 公共底座：`unaligned_common.py`（380 行）

**定位**：三模态提取的**公共底座**，就地替换 `utils.py` 的三处已知缺陷（docstring 逐条说明，均在本批 100 条 mp4 上实测确认）：

1. **时长口径**：`utils.get_video_duration()` 用「帧数/fps」估算，容器帧数虚高 → 改用 ffprobe 流时长 + 逐帧 PTS。
2. **抽帧方式**：`utils.safe_read_video_frames()` 全量载入内存（0.7 GB/片段）→ 改**流式逐帧 + 真实 PTS 触发**（任何时刻内存只持一帧）。
3. **音频临时文件冲突**：旧 `extract_audio_from_video` 的临时 wav 仅以 `clip_id.wav` 命名，而 100 条样本只有 **19 个不同 `clip_id`**（clip `"2"` 出现在 12 个不同视频中），"已存在则跳过"会导致**覆盖后静默复用**（实测 `-ri04Z7vwnc_0` 与 `-wny0OAz3g8_0` 音频特征逐字节相同）→ 改用 **ffmpeg 管道解码到内存，不落临时文件**。

**时间基准契约**：所有未对齐文件必须自带 `features (T,D) float32` + `pts (T,) float32`（相对片段起点，秒）。音频 pts 由 hop 恒定推出（等间隔），视觉 pts 由解码器实测（可能不均匀）。

**模块级副作用**：① 把 `code/` 插入 `sys.path`；② 对 `("stdout","stderr")` 调 `reconfigure(encoding="utf-8", errors="replace")`（防 Windows GBK 控制台在日志中文处抛 `UnicodeEncodeError` 中断整批）；③ `FFMPEG = _find_bin("ffmpeg")`、`FFPROBE = _find_bin("ffprobe")` **在 import 时即求值**，故 PATH 变更需重启进程。

### 5.4 L1 文本提取器：`unaligned_text.py`（390 行）

**定位**：文本模态提取，只做「文本 → 词级 RoBERTa 向量 `(W,768)`」，**不做时间槽分配**（`meta.alignment_rule` 一律写「无（本文件不做时间槽分配，对齐见 align_multimodal.py）」）。

**核心常量**：
- `TIME_BASIS = "uniform_assumption"`；`TIME_BASIS_DESC = "文本不含逐词时间戳，pts 为均匀分布假设：词 i 中心时刻 = (i+0.5)*duration/W。该时间轴仅用于与音频/视觉共轴可视化，不是实测值。"`
- `_CHAR_REPLACEMENTS = {"…":"...", "’":"'", "‘":"'", "“":'"', "”":'"', "—":" - ", "–":" - "}`（抽成常量让两条预处理路径共用，避免口径漂移）

**结构清单**：

| 名称 | 作用 |
|---|---|
| `preprocess_text(text)` | 字符替换 + 空白折叠；**刻意不做停用词过滤与去标点**（情感线索分布在全部词上） |

| **类 `UnalignedTextExtractor`** | RoBERTa 词级编码器 |
| └ `__init__(model_name=None, device=None, max_length=None)` | 惰性 import torch/transformers；`AutoTokenizer/AutoModel.from_pretrained` + `.eval()`；`feature_dim = hidden_size = 768`；`_special_ids = set(all_special_ids)` |

**依赖**：`numpy, torch, transformers`（延迟）；`config, unaligned_common, utils`；**无任何 LLM/HTTP API 调用**（全仓库 `openai|anthropic|api_key|requests.post|http` 零命中）。

### 5.5 L1 语音提取器：`unaligned_audio.py`（317 行）

**定位**：语音模态提取，只做「音频 → 逐帧 74 维 + 实测 pts」，@**20 Hz**。

**核心常量与公式**：
- `OFFICIAL_RATE_HZ = 20.0`（由附件2 的 500 帧上限与最长片段 25 s 反推：500/25 = 20 Hz）；`ENVELOPE_RATE_HZ = 100.0`（10 ms 一格振幅包络）
- `hop = int(round(16000/20)) = 800`（50 ms）；`frame_time_convention = "pts[k] = k * hop / sr（librosa center=True，帧中心时刻）"`
- **74 维构成**（`DIM_LAYOUT`）：
  | 区间 | 内容 |
  |---|---|
  | 0–19 | MFCC 20 维 |
  | 20–39 | ΔMFCC 20 维 |
  | 40–59 | ΔΔMFCC 20 维 |
  | 60 | log F0（pyin，`fmin=65.0, fmax=400.0`；清音帧填 `log(65.0)`） |
  | 61 | 浊音概率 |
  | 62 | log RMS（`amplitude_to_db(ref=1.0)`） |
  | 63 | ZCR |
  | 64 / 65 / 66 / 67 | 谱质心 / 谱带宽 / 谱滚降（`roll_percent=0.85`）/ 谱平坦度（`power=2.0`） |
  | 68–72 | 谱对比度 5 维（`n_bands=5` 后取 `sc[1:6]`） |
  | 73 | VAD 指示 |
- **VAD 规则**：`thr = max(1e-3, 0.05 × percentile(rms, 95))`；`vad = (rms > thr) & voiced`（须同时满足能量门限与 pyin 判浊）
- **维度硬断言**：`feats.shape[1] != 74` 抛 `RuntimeError` 并打印全部通道长度

**结构清单**：`_spectral_contrast5(...)`；**类 `AudioFrameExtractor`**（`__init__` / `extract_frames(y)`）；`envelope(y, sr, rate=100.0)`；`extract_one(extractor, sample)`；`run(samples, out_dir, overwrite=False, rate_hz=20.0)`；`main(argv=None)`。

**实现要点**：凡显式传 `S=` 的谱特征**必须同时传 `n_fft`**（librosa 默认 2048 会拿它校验 S 行数，实测曾抛 `ParameterError: Since S.shape[-2] is 513, frame_length is expected to be 1024`）；所有通道按 `T = min(...)` 截齐；`extract_frames` 的 meta 13 键含 `voiced_ratio/vad_ratio/vad_threshold/dim_layout/f0_range_hz` 等。

**输入输出**：读 `*.mp4` 音轨（ffmpeg 管道）；写 `data/unaligned_features/audio/<sample_id>.npz`，`extra = {"envelope": …, "envelope_times": …, "envelope_rate_hz": 100.0}`。

**入口**：`--only / --limit / --overwrite / --out / --rate`（默认 20）。

### 5.6 L1 视觉提取器：`unaligned_vision.py`（312 行）

**定位**：视觉模态提取，只做「视频 → 逐帧 35 维人脸深度特征 + 实测 pts」，@**15 Hz**（依据：实测 18 条与官方重叠样本的视觉帧数中位数对应 14.7 Hz，故取 15）。

**特征口径（与既有流水线严格一致）**：`MTCNN(image_size=160, keep_all=False)` 裁人脸 → PIL `Resize(224)` → `ToTensor` → ImageNet 归一化 → ResNet-50 去掉 fc 的全局平均池化 **2048 维** → **固定随机投影降到 35 维**。

**核心常量与公式**：
- 投影矩阵 `build_projection_matrix(2048, 35, seed=42)`：`W ∈ R^{2048×35}`，元素 `~ N(0, 1/√2048)`（`scale = 1/√raw_dim`，使 `E‖Wᵀx‖² = ‖x‖²`，配合 JL 引理近似保距）
- `matrix_md5(mat)` = `md5(float32 连续化 tobytes)` → 实测 `992b29b991cd23f9…`（**与上一版已删除的 `vision_extractor.py` 逐元素相同**）
- MTCNN 参数：`image_size=160, margin=0, min_face_size=20, thresholds=[0.6,0.7,0.7], factor=0.709, post_process=False, keep_all=False`
- 归一化：`mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225]`

**结构清单**：`build_projection_matrix(...)`、`matrix_md5(...)`、`_fill_missing_faces(features, face_flags)`；**类 `UnalignedVisionExtractor`**（`__init__` / `extract_frames(video_path)`）；`extract_one(...)`；`run(...)`；`main(argv=None)`。

**缺失人脸策略**（视觉模态自身属性，故在本模块完成，使对齐模块对模态无感知）：0 个有效帧或全有效 → 原样；仅 1 个有效帧 → 整体复制该帧；否则逐维 `np.interp` 线性插值；一帧都没有 → 保持零向量并由 `meta.face_ratio=0` 标记不可用。

**输入输出**：读 `*.mp4`（OpenCV 解码 + ffprobe 探测）；写 `data/unaligned_features/vision/<sample_id>.npz`，`extra = {"frame_gaps": [...], "face_flags": [...]}`（`frame_gaps` 供 QC 核对抽帧均匀性、暴露 VFR）。

**入口**：`--only / --limit / --overwrite / --out / --fps`（默认 15）/ `--dim`（默认 35）/ `--threads`（经 `torch.set_num_threads` 生效）。

### 5.7 L2 对齐层：`align_multimodal.py`（507 行）

**定位**：问题一的**对齐层**（流水线第 4 步），把三条独立时间轴统一到同一根「片段秒轴」并离散成 `L=50` 槽，输出与附件2 完全同构的 `(50,D)` 张量。**不依赖 torch/cv2/librosa**（只读未对齐 npz + numpy）。

**结构清单（13 个函数）**：

| 函数 | 作用 |
|---|---|
| `slot_edges(duration, n_slots)` | `np.linspace(0, T, L+1, dtype=float64)` |
| `slot_centers(duration, n_slots)` | 槽中心时刻 |
| `time_to_slot(t, duration, n_slots)` | `floor(t/T*L)` 后 `clip(0, L-1)` |
| `slot_to_interval(k, duration, n_slots)` | `(e[k], e[k+1])`（`time_to_slot` 的逆） |
| `align_series(features, pts, duration, n_slots, method="time_bin", fill="interpolate")` | **核心单模态对齐**，返回 `(aligned (L,D) f32, valid (L,) bool, meta)` |
| `resolve_duration(loaded, policy="video")` | 确定公共轴 `T`：按 `("vision","audio","text")` 查 `meta.duration_used` / `container_video_duration`；`max_pts` 时回退 `max(last_pts)` |
| `align_sample(sample_id, unaligned_root, n_slots=50, method="time_bin", duration_policy="video", fills=None)` | 单样本三模态对齐 |
| `save_sample_aligned(out_dir, res)` | 单样本落盘 |
| `save_aggregate(out_dir, results)` | 汇总成附件2 口径 `aligned_50.npz` |
| `save_slot_time_map(out_dir, results, n_slots)` | 槽↔时间映射表 |
| `save_summary_csv(out_dir, results)` | 汇总 CSV |
| `run(samples, unaligned_root, out_dir, n_slots=50, method="time_bin", duration_policy="video", fills=None, overwrite=False)` | 驱动 |
| `main(argv=None)` | CLI |

**模块级常量**：`MODALITIES = ("text","audio","vision")`；`_FILL_DEFAULT = {"text":"zero", "audio":"interpolate", "vision":"interpolate"}`。

**核心算法细节**：
- **空输入短路**：`T_==0 or D==0 or duration<=0` → 整段置零，meta 记 `note`。
- **越界记账（A8）**：用 `raw_idx = floor(pts/duration*L)` 判定而非 `t > T`（`pts` 以 float32 落盘，`T≈9.3` 处 float32 舍入步长已达 `9.5e-7`，用 `t > T` 会把精度误差误报为越界）→ `units_clipped_to_last_slot` / `units_clipped_to_first_slot` / `units_beyond_duration`。
- **`time_bin`（默认）**：`np.add.at` 累加到 `acc (L,D) float64` 与 `counts (L,) int64`，`aligned = acc/counts`，`valid = counts>0`。
- **`interp`**：先 `argsort(kind="stable")` 去重（重复时间戳会让 `np.interp` 依赖顺序），再逐维 `np.interp`；`valid = (centers>=p_sorted[0]) & (centers<=p_sorted[-1])`（**插值结果是构造的**，只有落在采样时间范围内的槽才算有效）。
- **空槽补齐**：`fill=="interpolate"` 且有效槽 ≥2 → 按槽号 `np.interp`；`"nearest"` 或只有 1 个有效槽 → 取最近有效槽；都不可行 → 保持零向量。
- **meta 键**：`method, fill, num_units, empty_slots, valid_slots, valid_ratio, units_per_slot_mean/max, unit_counts, slot_unit_index, units_clipped_to_last_slot, units_clipped_to_first_slot, units_beyond_duration`。
- **精度决策**：`duration` 与 `slot_edges` **必须存 float64**（否则「恰好落在槽边界」的单元会差一个槽——实测 **12026 个非空槽里有 39 个不可复现**，全为短句文本）。
- **命名陷阱**：`official_id` 用 `U.official_id(*sid.rsplit("_", 1))`（4 个 video_id 自身含下划线，下辖 6 条样本；用 `replace("_","$_$",1)` 会波及 18/300 行）。

**输入输出**：读 `<unaligned_root>/<modality>/<sample_id>.npz`；写 `data/aligned/<sample_id>.npz`（键见 §3.4②）、`aligned_50.npz`（§3.4③）、`slot_time_map.csv`（12 列，逐样本逐槽）、`align_summary.csv`（11 字段，`utf-8-sig`）。

**入口**：`--only / --limit / --slots / --method {time_bin,interp} / --duration {video,max_pts} / --fill-text / --fill-av / --unaligned-root / --out`。

**⚠️ 实现问题**：`run()` 声明了 `overwrite` 形参但**函数体内从未使用**（实际恒为覆盖写）；`main()` **恒返回 0**，样本全失败时 CLI 依然「成功」退出。

### 5.9 L3 编排：`run_unaligned_all.py`（206 行）

**定位**：一键跑通「提取 → 对齐 → 可视化 →（可选）问题一验收」四到六步的**唯一流水线驱动器**。

**结构清单**：`run_vision_watched(samples, out_dir, overwrite, sample_timeout, threads) → int`（返回超时样本数）；`main(argv=None)`。

**视觉看门狗（重要设计）**：视觉依赖 torch/OpenCV 的**原生线程**，实测出现过**非确定性卡死**——某条样本在批量运行中 8 核满载空转数小时不返回，同一条样本单独重跑不到 1 秒。卡死发生在原生代码内部，Python 层进程内计时器无法中断，故**每样本起一个子进程**，父进程按墙钟超时收割（`subprocess.run(cmd, timeout=...)`），超时则记日志并打印可直接复制的重跑命令。

代价：每样本多一次解释器与模型加载（≈2 s）。收益：① 卡死只影响自身；② 超时明确入日志；③ 因提取器默认跳过已存在产物，**重跑即断点续跑**。

**入口参数**：

| 参数 | 默认 | 说明 |
|---|---|---|

### 5.10 L4 取证：`face_probe.py`（658 行）

**定位**：「多人或远景」类别的**轻量人脸探测取证**。存在理由：`unaligned_vision.py` 的 MTCNN 是 `keep_all=False, post_process=False`——每帧只返回**一张**裁好的人脸（按框面积选最大者），**不保留任何框坐标**，因此逐帧结果里只有「有没有人脸」这个布尔量；没有框就分不出「一个人占满屏」与「五个人各占一角」，也没有框面积就分不出「近景大脸」与「远景小脸」。

本模块因此**另建一个 `keep_all=True` 的探测器实例**（其余参数与提取器**完全同参**，这是「同一探测器、同权重」说法的依据），对每条样本只做**纯检测**（不跑 ResNet 前向、不写特征），抽样取 **3 帧**（`0.15T / 0.50T / 0.85T`），记录每帧检出人脸数与框面积占比。**不产出也不修改 `data/unaligned_features/` 与 `data/aligned/` 的任何文件**。

**四条诚实边界**（docstring 要求随结果一并声明）：
1. **抽样下界，不是全片最大值**——3 帧都没拍到第二个人时，结论只能是「抽样未发现多人」，**不构成「该片段只有一个人」的证据**。
2. **探测帧与特征帧不同格**——提取器按 15 Hz 在实测 PTS 上取帧，本模块按固定比例取帧，最近可差约 `1/15 s`；故「探到人脸 ⇔ 提取器该帧有 face_flag」只作**一致性交叉核对**（`agree_with_extractor`）报出，不作硬断言。
3. **探测失败不等于没有人脸**——失败/超时写 `detector_ok=0` + 状态码，判据标为**不可用**，绝不写成「0 张脸」；也**不因此剔除任何样本**。
4. 逐样本独立子进程 + 墙钟超时（沿用 `run_vision_watched` 的模式）。

**结构清单（15 个函数）**：`_build_detector(threads=None)`、`_read_frame_at(cap, t_sec)`、`_clip_area_ratio(box, w, h)`、`probe_one_sync(video_path, duration, fracs, threads=None, detector=None)`、`_worker_main(argv)`（子进程入口）、`_nearest_vision(pt, vpts)`、`_load_vision_evidence(sid)`、`_to_float_list(...)`（**死函数**）、`_aggregate(sid, video, duration, payload)`、`_spawn_one(...)`、`run(...)`（内嵌 `flush()`）、`_read_csv_rows(path, fields)`、`_read_csv(path, fields)`、`_write_csvs(...)`、`main(argv=None)`。

**关键约定**：
- **三值约定**：`max_face_count` / `max_face_area_ratio` / `box_area_ratio_median` 在「探测成功但 0 张脸」时为 `0` / `0.0` / `0.0`，在「判据不可用」（`detector_ok=0`）时为 `-1`。「**0 张脸也是结论，因此默认取 0 而不是 -1**」。
- **判据看的是帧能否解码**，不是脸数：`ok = [r for r in rows if r["status"]==OK]`，`detector_ok = 1 if ok else 0`。
- **框面积占比必须先裁到画面内再算**（MTCNN 的框可越出边界，不裁会得到 >1 的占比）。
- **抽样比例基准是公共时间轴的 `T`**（读 `data/aligned/<sid>.npz` 的 `duration`，已按 D1 修复存 float64）。
- **续探判据不是「样本行存在」，而是「帧行数也齐」**（`n_frame_rows[sid] == n_frames`）。注释记录真踩过的坑：先用 `--only` 单探一条做冒烟测试（只落 1 帧行），之后全量运行时因「样本行已存在」跳过它，于是它的 3 帧证据永远缺 2 帧，而汇总表看起来完全正常。
- **逐帧表必须用 `_read_csv_rows` 而非 `_read_csv`**：后者按 `sample_id` 建字典，而逐帧表每个 sample_id 有 3 行，一建字典就只剩最后一行（本项目真踩过：续探时 `old_frames` 由 297 行缩成 100 行）。结论一句：**一张表能不能按主键建字典，取决于主键在表里唯不唯一。**
- **整表重写**：`flush()` 把「本轮新探 + 盘上已有」合并后**整表重写**，保证文件在**任何**时刻都是完整的 100 行。
- 临时目录必须用 `shutil.rmtree` 清理（`os.rmdir` 遇非空抛 `OSError` 且被吞掉，会让临时目录留在交付目录里被算进体积，实测 `0.087 MB`）。

**输入输出**：读源视频、`data/aligned/<sid>.npz` 的 `duration`、`data/unaligned_features/vision/<sid>.npz` 的 `pts` 与 `extra.face_flags`、断点续探用已有两份 CSV；写 `data/q1_delivery/face_probe.csv`（**23 列** / 100 行）与 `face_probe_frames.csv`（**17 列** / ≤300 行），`utf-8-sig`。

**入口**：`--out / --only / --fracs`(0.15,0.5,0.85) / `--timeout`(180.0) / `--threads`(4) / `--overwrite`。`main` 有**双分支**：解析前先看 `"--json-out" in argv`，命中则转 `_worker_main`（子进程分支），避免与父进程参数混淆。末尾以 `res["n_frames_total"]`（**盘上实际行数**）而非 `len(res["frames"])`（本轮新探帧数）打印日志。

### 5.11 L5 验收：`q1_verify.py`（1111 行）

**定位**：问题一交付前的**机器核验套件，只读、不修改任何产物**。把赛题的三条要求写成 **12 项可重跑谓词（V1–V12，另含子项 V1b）**，输出 `verify_report.json` / `verify_report.md`。

**12 项检查**：

| 项 | 名称 | 判据要点 |
|---|---|---|
| **V1** | 覆盖完整性 | **双向集合相等**：6 个集合（label-100 官方 / 三模态未对齐 / 单样本对齐 / aligned_50.npz）两两比对 `missing / extra / disagree`；含 `len(ref)==100` 显式检查 |

| **V2** | 词区间单调且不越出视频范围 | 文本 pts 严格递增；字符区间单调且**可回指**（`processed[s:e] == w`）；词元索引严格递增无重复；AV pts 非递减；**caveat 明写「本项由构造保证成立，不作为词级时间正确的证据」** |
| **V3** | 序列长度与词索引一致 | 文本 6 个长度字段必须全相等（`features.shape[0] / len(pts) / words / num_words / char_spans / token_index`）；各模态维度/掩码/长度自洽；对齐侧**三重相等** `valid.sum() == meta["align"]["valid_slots"] == (counts>0).sum()` |

| **V8** | 时长口径交叉核对 | **外部 ffprobe** 重探 100 条，失败阈值 `dev > 1e-3` |

### 5.13 L5 典型样本：`q1_typical.py`（335 行）

**定位**：**五类典型样本的「可复查选取规则」实现器 + 出图/出表调度器**。把「手工挑一条」变成「按极值判据自动挑一条」，判据写进 CSV 的 `criterion` 列。**没有 `main()`、没有 argparse、没有 `__main__` 块**——唯一入口是 `build_typical_pack()`，由 `q1_delivery.run_all()` 调用。

**五类判据（含真实常量）**：

| 类别 | 判据 |
|---|---|
| **长句** | `key=(-num_words, sample_id)` → 词数最多 |
| **短句** | `key=(num_words, duration_sec, sample_id)` → 词数最少，同词数取时长短者 |
| **停顿明显** | **候选池先剔除数字静音**（`audio_has_content`）；`key=(voiced_ratio, -duration_sec, sample_id)`。注释明确：**不能用 `voiced_ratio==0` 代替**数字静音判定（数字静音 A1 与「有能量但 VAD 判零」A2 的 `voiced_ratio` 都是 0） |

### 5.16 L6 问题2 特征装配：`emotion_features.py`（355 行）

**定位**：情感判定模型的**特征装配层**（唯一职责：把问题1 的 `(50,D)` 张量 + 逐模态有效掩码装配成二维设计矩阵，并把监督标签从 xlsx 关联进来）。**不做任何模型训练/评估**（那是 `emotion_model.py`）。单独成层的两个理由：① 池化规则「只在有效槽上池化」容易写错且写错不报错，集中一处实现使训练与消融共用同一口径；② 消融需按模态切片，切片边界必须与装配时一致，故由 `build_design_matrix` 通过 `meta` 显式返回。

### 5.17 L6 问题2 训练评测：`emotion_model.py`（806 行）

**定位**：情感判定模型的**训练、评测与报告层**。文件头 docstring 明确三条方法论红线：

1. **必须按视频分组划分**——100 条来自 37 个视频，随机划分会让同视频片段同时落在训练/测试折，模型可靠「认出这个视频」得分 → `StratifiedGroupKFold` + `video_id` 为组。
2. **超参必须嵌套选**——外层 5 折评估，超参在**每个训练折内**用内层 3 折选，避免超参泄漏。
3. **诚实性约束**——每个模型指标都与**该折自己的**多数类基线并列输出；一律报均值 ± 标准差。

另记录两个真踩过的坑：① out-of-fold 预测必须按原始下标写回 `oof[te] = pred`（若按折顺序 `np.concatenate` 拼接，相关系数会**假性掉到 ≈0**）；② 池化必须只在有效槽上做。

**模型注册表 `MODEL_SPECS`**：

| key | family | 网格 | 中文 |
|---|---|---|---|
| `ridge` | regression | `alpha ∈ {1, 10, 100, 1000, 10000}` | Ridge 回归 |
| `enet` | regression | `alpha ∈ {0.02,0.05,0.1,0.2,0.4} × l1_ratio ∈ {0.2,0.5,0.8}`（15 组） | ElasticNet 回归 |
| `mlp` | regression | `alpha ∈ {0.1, 1.0, 10.0}`，`hidden_layer_sizes=(64,)` | MLP 回归(64) |
| `logreg` | classification | `C ∈ {0.001,0.003,0.01,0.03,0.1}`，`class_weight="balanced"` | 逻辑回归(balanced) |
| `svc` | classification | `C ∈ {0.1, 1.0, 10.0}`，`kernel="rbf"`，`balanced` | SVC(rbf, balanced) |

注释说明：网格刻意做小——「n=100 下更大的搜索空间只是在拟合噪声」。

**结构清单（18 个函数）**：`make_splits`、`_build`、`macro_f1`（手算 one-vs-rest，避免 sklearn 版本口径漂移）、`confusion`、`evaluate_regression`、`per_class_recall`、`evaluate_classification`、`majority_baseline`、`nested_cv`、`_to_state`、`run_cv_comparison`、`run_ablation`、`run_holdout`、`_write_csv`、`build_prediction_rows`、`make_figures`、`write_readme`（内嵌 `fmt`）、`main`（内嵌 `_n`）。

**关键指标定义**：
- **`calib_slope`**：`np.polyfit(pred, y, 1)`（预测作自变量、真值作因变量）。**slope ≪ 1 说明预测被强烈向均值压缩**——「能排序但不敢给大幅度值」。
- **`balanced_acc`** = 三类召回率算术平均；**`recall_Neutral`** 是必须报告的一条（三分类准确率容易被「全猜 Positive」刷出来）。
- 多数类基线的 `MAE/r/rho` 显式写 NaN（类别编码 ±1 不是强度）；均值基线反之只报 MAE/r/rho。

**实测折大小**：`18 / 19 / 19 / 24 / 20`；held-out = **`splits[0]`（18 条，正 10 / 中 5 / 负 3，多数类基线 0.556）**，注释强调「该折是**先验取的第一折**，并非按表现挑选」。

**产物**：`cv_comparison.csv`（14 列）、`oof_predictions_all100.csv` 与 `test_predictions.csv`（同 **13 列** `PRED_COLS`，含 `face_ratio` / `vision_available`，使模态缺失分析可直接在此表上做）、`ablation.csv`、`fig_confusion.png`、`fig_scatter.png`、`fig_ablation.png`、`README_情感判定模型_运行结果.md`。

**实测主要结果（三模态口径，见 §8.6 的警告）**：Ridge MAE 0.527 / r +0.413 / ρ +0.505；逻辑回归(balanced) acc 0.630 / macroF1 0.493 / **中性召回 0.240**；所有**回归**模型的 **Neutral 召回率均为 0.000**（从不输出落在死区内的预测）。模态消融：**文本独大，语音为负贡献**（audio 单独 r = −0.103），text+vision 略优于三模态。

### 8.7 结论口径类风险（必须与数字一起读）

1. **文本没有真实的逐词时间戳**——附件1 只提供整句转写，附件2 也不存逐词时间戳。词级时刻只能来自假设 `(i+0.5)·T/W`（功效最弱的假设）。**本项目不声称达到任何毫秒级的对齐平均误差**——没有逐词人工真值就没法量化它；只报告一致性检查（可逆映射、溯源重算、边界单调）与人工抽查结果。
2. **`*_valid` 掩码不能用来判断模态可用性**（插值与零填充同样被标 `True`），判断要用原始 `face_ratio`。
3. **不删样本**——以置信度阈值删除样本会偷偷改变测试集分布；异常台账里 `counts_as_deletion` 恒为 0。
4. **问题2 的性能上限**：排序信号是真的（Spearman ρ 显著为正，p<0.01）；但**强度只能用于排序、不能用于绝对量级**（Ridge 在 100 条 oof 上预测标准差 0.224 vs 真值标准差 0.806，方差仅为真值的约 8%，预测被强烈压向均值）；**所有回归模型的中性召回率都是 0.000**，准确率全部来自对 Positive 的过预测；**文本独大，语音是负贡献**（audio 单独 r 为负）；held-out 只有 **18 条**，是**单次抽样、无置信区间**，其数值不应单独引用，主结论一律以 5 折 out-of-fold 均值为准。
5. **N=100 不能支撑的结论**：不能说「模型学会了情感」；不做特征重要性归因；不比较相近模型的细微差异；不外推到 MOSEI 全集或其他语料。若某模型指标落在基线标准差内，应表述为「与基线无显著差异」，不得包装成有效。
6. **五类典型样本里的两处「名不副实」**：①「多人或远景」只对每样本均匀抽 **3 帧**做纯检测，`max_face_count` 是**抽样下界**，不是全片最大人脸数——抽样未发现多人时该类别如实以「远景/小脸」实例呈现，而不是硬造一个多人样本充数；②「面部检测失败」选中的 `-ri04Z7vwnc_0` 经查关键帧，是**画面里本来就没有人的动画素材**，即「检测失败」的真实原因是「没有人脸存在」而非「检测器漏检真人」——**只有保留关键帧才能区分这两种情况**，这正是交付里保留少量关键帧的理由。
7. **语音 74 维是等价维度代理**（无 COVAREP），论文中必须如实标注，不能声称用了 COVAREP。
8. **交付物体积用更严口径**（50 MiB = 52,428,800 B）；冻结的 RoBERTa 本体约 440 MB **无法随交付提交**，故只固定其版本、来源与校验值。

## 9. 附录

### 9.1 术语表

| 术语 | 含义 |
|---|---|
| **未对齐（unaligned）** | 各模态保留自身采样率与实测时间戳、不强行等长的中间形态 |
| **对齐（aligned）** | 三模态按「秒」投到同一轴后离散成的 `(50,D)` 定长形态 |
| **槽（slot）** | 公共时间轴上的等分区间，`L=50`，槽宽 `T/L` |
| **槽宽 / 对齐粒度** | `T/50`，本批 45 ~ 586 ms |
| **溯源（traceability）** | 槽 → 未对齐单元下标 → 原文词 / 帧时间戳 的完整链（靠 `slot_unit_index`） |
| **`time_basis`** | 时间轴来源：`measured_pts`（实测，音/视觉）或 `uniform_assumption`（假设，文本） |
| **`valid_mask`** | 「该槽被分配到采样单元」的标志，**不等于真观测** |
| **看门狗（watchdog）** | 逐样本子进程 + 父进程墙钟超时收割，绕开 torch/OpenCV 原生线程的非确定性卡死 |
| **嵌套 CV** | 外层 5 折评估、超参在每折内层 3 折选，防超参泄漏 |
| **out-of-fold（oof）** | 每个样本由「没见过它」的那一折模型给出的预测 |
| **`calib_slope`** | 校准斜率；≪1 表示预测被压缩向均值（能排序但不能给绝对量级） |
| **D1 / D2 / D3** | 本项目发现并修复的三处真实缺陷：D1 `duration` 降精度致槽归属不可复现；D2 `official_id` 按首个下划线切分；D3 逐帧表被按主键建字典致证据丢失 |
