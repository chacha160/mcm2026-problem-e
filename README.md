| 列 | 含义 |

| `text` | 该片段的英文转写文本（**整句，无逐词时间戳**——这一点决定了问题1 的关键假设，见 §7.1） |

| `annotation` | 极性文字标签 `Negative` / `Neutral` / `Positive`，本批 100 条实测**恰为 `sign(label)`**，零例外 |

### 1.4 两处必须说清的**输入口径差异**（实测，非推测）

1. **赛题正文写的时长区间与文件实际不符。**
   正文称附件1「所有视频时长介于 2.648 秒和 34.567 秒之间」。用 `ffprobe` 对全部 100 个 mp4 实测（格式时长与视频流时长两个口径**完全一致**）：
   **实为 2.257 ~ 29.288 s**。其中 `-mJ2ud6oKI8_6`(2.257 s)、`-s9qJ7ATP7w_6`(2.475 s) **短于下限**，且**没有任何一条达到上限**（最长为 `-yRb-Jum7EQ_1` 的 29.288 s）。
   本项目全流程以 **ffprobe 实测值**为准，不按正文区间做任何裁剪或补长；`q1_verify.py` 的 V8 项会用外部 `ffprobe` 重新核对 100 条时长。

2. **不能用「帧数 ÷ fps」估时长。**
   本批 mp4 的容器帧数虚高 1.5~2.6 倍（例：`-3g5yACwYnA/2.mp4` 容器声称 424 帧 @30 fps = 14.13 s，实际只解出 278 帧、真实时长 9.39 s）。旧工具 `utils.get_video_duration()` 正是这么算的，会把时间轴整体拉长。现流水线一律用 ffprobe 流时长 + 逐帧实测 PTS。

### 4.2 各模态特征怎么提

| 模态 | 方法 | 维度 | 时间基准 |
|---|---|---|---|
| **文本** | 冻结的 `roberta-base` → 末层隐状态，子词按词平均 → 词级向量 | 768 | `uniform_assumption`（**假设**） |
| **语音** | `librosa`：MFCC 20 + ΔMFCC 20 + ΔΔMFCC 20 + logF0 + 浊音概率 + logRMS + ZCR + 谱质心/带宽/滚降/平坦度 + 谱对比度 5 + VAD | 74 | `measured_pts`（实测） |
| **视觉** | MTCNN(160) 裁人脸 → Resize(224) → ResNet-50 池化 2048 维 → 固定随机投影（seed=42）降维 | 35 | `measured_pts`（实测） |

- **维度严格对齐附件2**（768 / 74 / 35、序列 50 槽），因为赛题要求附件4 与附件2 保持同一维度口径。
- 语音的 74 维是**等价维度代理**：官方 74 维来自 COVAREP（含声门参数），本机无 COVAREP，改用「MFCC + 差分 + 韵律 + 频谱」凑满 74 维并**逐段写进文件元数据**以便复核。这一点在论文里必须如实标注，不能声称用了 COVAREP。
- 视觉投影矩阵与上一版已删除的 `vision_extractor.py` **逐元素相同**（md5 `992b29b991cd23f9…`），md5 随每个文件落盘，任何一次运行都能验证用的是不是同一个投影。

### 4.3 对齐规则（问题1 的核心）

> 以片段真实时长 `T` 为公共时间轴，把 `[0,T]` 等分为 `L=50` 个槽（槽宽 `T/L`）；
> 每个未对齐单元按其**实测时间戳**归属到所在槽，同槽内特征取**均值**；
> 空槽按策略补齐并在 `valid_mask` 中标 `False`。

三条关键约定：

1. **按「秒」归属，不按数组下标。** 三模态采样率不同（音频 20 Hz、视觉 15 Hz、文本按词），按下标等分会把 50 ms 的音频帧和 66.7 ms 的视觉帧当作等长，并抹平丢帧/VFR 的不均匀间隔。
2. **三模态共用同一个 `T`。** `T` 取自 ffprobe 视频流时长，提取阶段就写进了各模态的 `meta`，因此**对齐这一步不需要原始视频**，仅凭未对齐特征文件就能独立重跑。
3. **空槽策略按模态疏密分别设定**：文本 `zero`（一段 5 s 的话只有十几个词，天然填不满 50 槽；补零才诚实，插值会制造原文不存在的「词」）；语音/视觉 `interpolate`（采样率远快于槽率，空槽只可能出现在音轨短于视频处）。

**槽 ↔ 时间是可逆的闭式映射**，这是问题3「关键证据定位」能回落到真实时段的前提：

```
槽号 → 时间： [k·T/L, (k+1)·T/L)
时间 → 槽号： min(L-1, floor(t·L/T))
```

### 4.4 溯源链（比闭式公式更强的一环）

每个槽同时记录「哪些未对齐单元落进了它」（`slot_unit_index`），于是这条链是完整的：

```
槽号 → 未对齐单元下标 → 该单元的原文词 / 该帧的时间戳
```

`q1_verify.py` 的 V4 项正是用这条链做**反向重算**：取每槽的源单元重新求均值，要求与落盘槽值**逐元素精确相等**。这条检查曾抓出一个真实缺陷（`duration` 落盘时被降成 float32，导致 39 个槽的槽归属无法复现），修好后违例归零。

### 4.5 问题2 的建模逻辑（简述）

对齐特征 → 按**有效槽**池化（文本仅均值 768 维；音频/视觉 均值+std → 148/70 维，合计 986 维）→ 设计矩阵 → 按**视频分组** 5 折交叉验证（`StratifiedGroupKFold`，以 `video_id` 为组，防同视频片段跨折泄漏）→ 超参在**每个训练折内部**用内层 3 折选（嵌套，防泄漏）→ 回归给强度、分类器给状态。

三条铁律写在 `code/README_情感判定模型.md` §4，其中「out-of-fold 预测必须按原始下标写回」是本项目实际踩过的坑（按折序拼接会让相关系数假性掉到 ≈0）。

## 7. 诚实边界：哪些结论**不能**下

### 7.1 文本没有真实的逐词时间戳

附件1 只提供整句转写，附件2 也不存逐词时间戳。因此词级时刻只能来自**假设**：
`词 i 的中心时刻 = (i + 0.5)·T/W`（「词在已知片段总时长内均匀分布」，功效最弱的假设）。
每个文件的 `meta.time_basis` 字段如实记为 `uniform_assumption`，与音频/视觉的 `measured_pts` 区分开。

**因此本项目不声称达到任何毫秒级的对齐平均误差**——没有逐词人工真值就没法量化它。只报告**一致性检查**（可逆映射、溯源重算、边界单调）与**人工抽查**结果。

### 7.2 `*_valid` 掩码**不能**用来判断模态可用性

`valid=True` 只表示「该槽被分配到了采样单元」，**不表示该单元是真观测**——插值与零填充同样被标 `True`。
反例：`-mJ2ud6oKI8_1` 的 `vision_valid` 是 50/50 全 `True`，但视觉特征能量**恰为 0.0**（MTCNN 一帧人脸都没检出）。
判断模态是否真的可用要用原始 `face_ratio`。

### 7.3 不删样本

以置信度阈值删除样本会**偷偷改变测试集分布**。本批的退化样本（音轨数字静音、人脸全失败、视觉能量为 0）**全部保留**在 100 行汇总、特征与台账里，只如实标注异常代号。
异常台账里的 `counts_as_deletion` 恒为 `0`。

### 7.4 问题2 的性能上限（必须与数字一起读）

- **排序信号是真的**：Spearman ρ 显著为正。
- **强度只能用于排序，不能用于绝对量级**：预测被强烈压向均值，大幅情感值基本预测不出来。
- **回归模型从不预测「中性」**：所有回归模型的中性召回率都是 **0.000**，准确率全部来自对 Positive 的过预测。状态判定应使用专用分类器，而非回归取符号。
- **文本独大，语音是负贡献**：消融中 audio 单独 r 为负。
- `held-out` 只有 18 条，是**单次抽样、无置信区间**，其数值不应单独引用；主结论以 5 折 out-of-fold 均值为准。

### 7.5 五类典型样本里的两处「名不副实」，必须照着说

- **「多人或远景」**：本批只对每样本均匀抽 3 帧做纯检测，`max_face_count` 是**抽样下界**，不是全片最大人脸数。抽样未发现多人时，该类别如实以**「远景/小脸」实例**呈现，而不是硬造一个多人样本充数。
- **「面部检测失败」**：选中的 `-ri04Z7vwnc_0` 经查关键帧，是**画面里本来就没有人的动画素材**。也就是说「检测失败」的真实原因是「没有人脸存在」，而不是「检测器漏检了真人」。**只有保留关键帧才能区分这两种情况**——这正是交付里保留少量关键帧的理由。

### 8.8 已修复：文本可用性口径曾不统一（导致附件4 出现「幽灵证据」）

`q2q3_common.analyze_sample` 早期对附件4（有 768 维 `text`）用「768 维特征非零即观测」判定文本可用性，
而附件2/3 用 `input_ids` 判定——两个口径不一致，既违反 L17 的「同一输入接口」，
又因 RoBERTa 对填充位置同样输出非零向量，把填充槽判成了有观测。

后果：附件4 `01` 号样本（`L=24`，词元区仅槽 1–22）的注意力 softmax 里混进了槽 23–49，
`explanation_cards.md` 于是列出槽 27/32/45 作为「关键证据」，
但它们在时间轴和原始文本上都映射为空——而赛题 L28 要求关键证据必须能定位到
真实的原始文本片段 / 语音时段 / 视觉关键帧，这类槽无法满足。

现统一为 `obs[text] = 词元区 & (input_ids != PAD_TOKEN_ID)`，三个附件共用一条规则。
核验：附件4 全部 20 条样本中 `obs_mask & padding` 为真的槽数 = 0，
`01` 号的 `observed[text]` 精确等于 `[1, 22]`。音视频未受影响
（四个附件中无任何样本在非词元槽上出现非零音视频特征）。
`data/q3/` 的全部证据产物已用修正后的口径重新生成。

### 8.9 已修复：关键帧图注声称「已打码」但实际从未打码

`q3_timebase._face_mosaic` 原用 OpenCV 自带 Haar 级联，但本机 OpenCV 5.0.0
**没有 `cv2.CascadeClassifier`**、`cv2.data.haarcascades` 下也没有级联文件，
于是每次都在「检测不可用」分支原样返回原帧，而 `keyframes_*.png` 的图注
始终写着 `faces mosaicked for anonymity`——**图里是清晰人脸，图上却声明打了码**。
这是一句与事实不符的声明，比不打码本身更严重。

现改用 MTCNN（`facenet-pytorch` 自带本地权重，纯离线，也是问题一视觉提取所用的同一检测器）。
实测 4 个样本的抽帧每帧均检出并打码 1 张人脸。同时把接口改成
`face_mosaic → (图, 打码数)`、`grab_frame(..., return_faces=True)`，
图注**据实生成**：检出 0 张时写「未检出人脸，故未打码」，而不是继续声称已打码。

### 8.10 已修复：问题三的归因一直带着 dropout 在跑

`q3_explain.py` 加载问题二模型后**从未调用 `model.eval()`**。
`nn.Module` 默认 `training=True`，于是解释路径里 `dropout(p=0.15)` 一直生效——
注意力占比、留一 Δ / KL / 翻转全部变成**随机量**：同一份模型文件重跑会得到
不同的解释结论（实测两次 `--init q2` 给出「主要参考模态 20/20」与「19/20」两种结果）。

问题二的指标不受影响（`q2_train.evaluate` 内部有 `model.eval()`），
只有问题三的解释路径中招。这与 §8.8、§8.9 是同一类错误的三种表现：
**一处静默失效的机制，让产物说了一件与事实不符的话。**

修复：加载后显式 `model.eval()`（`--init q2` 与 `--init train` 两条路径都加），
并在 `attribute_sample` 入口再兜一次 `model.eval()`，使任何调用方都不会漏掉。
修复后重跑两次结果逐位一致。
